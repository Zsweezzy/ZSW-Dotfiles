## 2026-09-28 — tokyonight quickshell config (first run)
- Repo facts: config at `~/.config/quickshell/tokyonight`, launched `quickshell -c tokyonight` (v0.3.1, Arch), hot-reloads on save. No build system; checks are `bash -n`, running the scripts, and the reload log.
- Verification without qmllint: `quickshell -c tokyonight log` — success is `Reloading configuration...` followed by `Configuration Loaded`; a failed reload keeps the OLD bar running and only pops an overlay, so never trust the screen. (2026-09-28 correction: `opencode debug lsp diagnostics` does NOT exist in opencode 2.0.18 — `debug` has only agents/config/paths. There is no qmlls, no qmlformat, and quickshell has no validate mode, so structural review plus manual read-through is the only QML check available.)
- `Quickshell.iconPath(name, true)` (0.3.1) resolves freedesktop theme names and returns "" on a miss; `hasThemeIcon()` is the predicate. Works with no `//@ pragma IconTheme` — the active GTK theme is picked up. A plain `Image { source: ... }` renders the result, SVG included.
- `TrayIcon.qml` + `scripts/icon-resolve.sh` were retired with the tray merge (the `find`-based resolver cost 3.9 s per miss; the built-in `iconPath` is better) and are **confirmed deleted from disk** as of 2026-10-03.
- Sub-agents on some providers refuse to run from this host ("free tier can only be used from within OpenCode") — retry with a different agent type.
- 2026-09-28: QML `Image.source` is url-typed, so `source === ""` is ALWAYS false (measured: `source === ""` false, `String(source) === ""` true). Test `icon.status === Image.Null` instead. A url/string compare as a visibility guard silently blanks cells and never throws.
- 2026-09-28: SNI `icon` is not a theme name — Steam sends a full `image://icon/steam_tray_mono?path=...` URL, others send `image://qspixmap/N/M`, openRGB sends an empty `IconName` (quickshell synthesizes a pixmap URL). Pass any `://` string through untouched; `Quickshell.iconPath` cannot resolve them.
- 2026-09-28: a sub-agent that edits a live config and dies (rate limit) leaves instrumentation behind. Always `cp` aside + restore + prove with sha256 against `git show HEAD:file`; check `git status` on the live file FIRST after any sub-agent error.
- 2026-09-28: only one process can own StatusNotifierWatcher, so a second `quickshell -p` probe sees 0 SNI items. Read tray state from the LIVE instance's log (instrument + `quickshell -c tokyonight log`) or from D-Bus directly (`busctl --user introspect :1.NNN /StatusNotifierItem`).
- 2026-09-28: a failed hot-reload leaves the OLD bar on screen, so the screen always looks fine. Only the log distinguishes success.
- 2026-09-28: `~/.config/hypr` is a SECOND config tree, separate from the quickshell one, and has NO git. Its only history is 7 `hyprland.lua.bak*` files. Binds live there; the ledger still lives under the quickshell tree. Expect to ask before `git init` it.
- 2026-09-28: `hyprland.lua` verification chain: `luac -p` (syntax only — it does NOT catch a nil `hl.dsp.*` field) -> `hyprctl reload` (once, live compositor) -> `hyprctl binds` (the real proof). A config that throws at load keeps the OLD config, so a bad field is invisible except as a bind that fails to appear.
- 2026-09-28: `hl.dsp.window.close()` exists in Hyprland 0.56.2 (graceful) alongside `hl.dsp.window.kill()` (SIGKILL). `repeating = true` is a real bind option already used at hyprland.lua:507-522 — it re-fires while the key is HELD, which is not the same as a self-paced "repeat until the window is gone" loop.
- 2026-09-28: Hyprland modmask arithmetic for spotting collisions: SUPER=64, CTRL=4, SHIFT=1, ALT=8. `hyprctl binds` output gives modmask+key, so three C binds coexist as 64 (kill), 65 (tray), 68 (close).
- 2026-09-28: the tokyonight bar talks to Hyprland ONLY via `hyprctl` through `Quickshell.execDetached`; the `Hyprland` singleton is imported for observation only (`onRawEvent`, `monitorFor`, `workspaces`, `focusedMonitor`), never dispatch. The bar has no `CustomShortcut`/`IpcHandler`/`Quickshell.Io` at all — reaching for a shell-side shortcut means building an IPC layer from scratch.
- 2026-09-28: **`hl.dsp.*` returns a descriptor, it does not fire on its own** — it only acts when handed to `hl.dispatch()` or `hl.bind()`. A bare `hl.dsp.window.close()` statement is a silent no-op (forum #1591; "bites people constantly"). Passing it to `hl.bind()` IS the working path, which is why the `SUPER+CTRL+C` bind needs no wrapping.
- 2026-09-28: **Hyprland does not escalate repeated close requests.** `close()` re-sends the identical `xdg_toplevel.close` / `WM_DELETE_WINDOW` forever. So a "keep re-asking until it dies" loop does NOT rescue an app that genuinely ignores the request — it only covers a first request eaten by a `noclosefor` window rule (repeat requests then rejected with "can't close window, it's not closeable yet" until the window ages in). Repeating is near-worthless; a grace period then SIGTERM/SIGKILL is what actually escalates.
- 2026-09-28: `hl.dsp.window.signal({signal=N})` exists (N 1-31), and `hl.timer(fn, {timeout=ms, type="repeat"|"oneshot"})` is a real native timer (no `hl.sleep`, no coroutine yield point). A keybind callback gets 100 ms, a timer callback 50 ms. Timers must be held in a variable outliving the callback — `onTimerFire` gates on `strongRef() > 2` and drops otherwise. That is how a self-paced close loop would be built with no shell script; not built, user chose the single request.
- 2026-09-28: XWayland caveat — `close()` sends `WM_DELETE_WINDOW` only if the app advertises it, else `xcb_kill_client`, a hard kill. On such apps the "graceful" bind is a kill with extra steps, silently. Native Wayland apps that ignore the request are simply left open.
- 2026-09-28: `hyprctl dispatch closewindow` is BROKEN under a Lua config — HyprCtl rewrites the arg to `hl.dispatch(<arg>)`, and the legacy names (`closewindow`, `killactive`, `forcekillactive`) are hyprlang-only. Under Lua you must write `hyprctl dispatch "hl.dsp.window.close()"`. Also note `killactive` == graceful close and `forcekillactive` == SIGKILL: the names read backwards.
- 2026-09-28: `quickshell -c tokyonight log` prints the WHOLE journal since instance start, not just the last reload. Removed instrumentation still shows up as historical output. Scope every claim to lines after the LAST `Configuration Loaded` — otherwise you will "discover" a bug that was fixed runs ago.
- 2026-09-28: `Quickshell.iconPath(name, true)` is CASE-SENSITIVE. Measured: `"samrewritten"` -> `image://icon/samrewritten`, `"SamRewritten"` -> `""`, `hasThemeIcon` agrees. A window class like `org.samrewritten.SamRewritten` therefore misses even though the icon exists at `/usr/share/icons/hicolor/64x64/apps/samrewritten.png`. Retry the last dotted segment lowercased, but try lower case LAST — `org.openrgb.OpenRGB` resolves only in its own casing.
- 2026-09-28: **nerd-font codepoints are not what the FA4 name suggests.** U+F0C8 is `fa-square`, not a wrench — that IS U+F0AD. A wrong "generic" glyph therefore renders as a literal box and gets reported as a broken icon. Verify a codepoint with fontTools (`getBestCmap` can return a list — merge `f['cmap'].tables` that are `isUnicode()`), and resolve the family with `fc-match` FIRST: family "JetBrains Mono Nerd Font" maps to the *Proportional* `JetBrainsMonoNerdFont-Regular.ttf`, not the Mono face, so checking the wrong file proves nothing.
- 2026-09-28: `RegisteredStatusNotifierItems` on `org.kde.StatusNotifierWatcher` is a D-BUS **property**, not a method — `busctl --user call` fails with "No such method". Use `busctl --user get-property org.kde.StatusNotifierWatcher /StatusNotifierWatcher org.kde.StatusNotifierWatcher RegisteredStatusNotifierItems`, then `introspect` each returned `:1.NNN/path` for `IconName`/`Id`/`Title`. This is how to find out that only 2 of your "tray" apps are real SNI items.
- 2026-09-28: verify quickshell UI with `grim` + pixel analysis instead of screenshots. Pick the monitor by name from `hyprctl monitors -j` (`grim -o 0` fails). `grim` captures PHYSICAL pixels, so logical = /2 at scale 2 — a slip here silently analyses the wrong region. `pillBg` at alpha 0.9 composites to about (44,48,72) over bar bg (22,22,30). A glyph is sparse strokes; a solid box is ~98% fill with <40 distinct colours; artwork is 100+ distinct colours. Count pixels matching a colour with ALL channels within tolerance — an ANY-channel match is far too loose and reports AA fringes as glyphs.
- 2026-09-28: `pgrep -f 'hyprctl|jq'` matches its own command line and reports a permanent phantom process count. Use `pgrep -xc <name>` for exact-name counting when measuring whether a poll actually spawns anything.
- 2026-09-28: the tokyonight QML files use 4 spaces — `grep -cP '\t'` is 0 across all of them. Do not tell a sub-agent to use tabs; verify the file's actual convention first.
- 2026-09-28: when a reviewer or brief asserts a premise, check it before complying. Two of this run's briefs were wrong (a `SUPER+CTRL+SHIFT+C` bind that never existed; "tab indentation" against a spaces repo) and a review finding was rejected because its stated reason was false (`Bar.qml`'s unused `Quickshell.Hyprland` import was already an orphan at the base commit, so it was not residue of the diff). A finding with a false premise is worse than no finding — executing it enlarges the diff for nothing.

## 2026-10-03 — notifications pinned to the primary screen; × looked inert
- **`Hyprland.focusedMonitor` is FROZEN in Quickshell 0.3.1.** `HyprlandIpc::setFocusedMonitor()` (`src/wayland/hyprland/ipc/connection.cpp`) assigns `bFocusedMonitor` and never emits `focusedMonitorChanged`; the property is `isReadonly: true` with `notify: focusedMonitorChanged`. Every QML binding on it evaluates once at startup and never again. Measured live: read `"DP-1"` continuously since the 11:21 instance start. Read it as "the monitor focused at startup", never as "the focused monitor". Workaround for live focus: `Hyprland.rawEvent` — for `focusedmon`, `String(event.data).split(",")[0]` is the monitor name.
- **`PopupWindow.screen` is the parent's, but only once the window exists.** `setScreen()` is a rejected no-op (`WARN scene: QML PopupWindow: Cannot set screen of popup window, as that is controlled by the parent window`) and `PopupPositioner::reposition()` never calls it. `ProxyPopupWindow::deleteOnInvisible()` is `true`, so a popup with `visible: false` has NO `QWindow`, and `ProxyWindowBase::qscreen()` then returns `QGuiApplication::primaryScreen()`. Measured with a throwaway 3-monitor probe: all three popups report `DP-1` at `Component.onCompleted`, correct per-monitor identity only from ~t2500. **Any gate that reads `popup.screen` at construction or before first show silently reads the primary screen.** Pass the parent's screen in from the `Variants` delegate instead.
- The two together were one bug: frozen `wantScreen`(=DP-1) + all-monitors-reporting-DP-1 ⇒ `mine` true on every Toast ⇒ one Notification pushed into three private `rows` arrays ⇒ drawn on three monitors ⇒ × removes one copy and the other two look like it never worked. The × code was never broken.
- Do not conclude a popup's screen from `Component.onCompleted`. Measured with a probe config in /tmp, run on the real display with `timeout` — `QT_QPA_PLATFORM=offscreen` has one fake screen and cannot answer this.
- `Hyprland.monitorFor(screen)` takes a **Qt** `QScreen`/`QuickshellScreenInfo`, not a `ShellScreen` (`Workspaces.qml` passes the bar's `ShellScreen`).

## 2026-10-02 — timer regressions + notification centre restyle
- **`touch <file>.qml` does NOT trigger a quickshell reload.** It only raises `IN_ATTRIB`; the watcher reacts to real writes. Cost a false alarm that the watcher had died and the bar needed restarting after a failed load. It had not — appending one byte reloaded clean immediately. **Never conclude the watcher is dead from a bare `touch`; write a real byte, or the temptation is to kill the user's bar for nothing.**
- `quickshell ipc call` is a dead end here: it needs an `IpcHandler`, and this config has none (same finding as the no-`Quickshell.Io` note above). Reload-on-save is the only path.
- Offscreen probe: `QT_QPA_PLATFORM=offscreen timeout 12 quickshell -c tokyonight` distinguishes a **parse** error from a platform error — it gets through `shell.qml` -> `Bar.qml` and stops at `Bar.qml[26:5]: No PanelWindow backend loaded`. It is **not** full validation: Bar fails first, so nothing under it (TimerPanel, TimerCreator, the flyouts) is ever reached.
- `Repeater { model: <reassigned immutable array> }` rebuilds every delegate on each write, so any write from a pointer-move handler destroys the `MouseArea` holding that press. Drag must hold state locally and write **once, on release**. This is why the timer row's scrub looked completely dead rather than flaky.
- The grab strip's `z: 10` was silently cancelling its own declaration-order comment: z orders siblings regardless of declaration order, so the 18 px strip sat ON TOP of the three PillButtons and ate the bottom of their click area. A comment describing intent is not evidence of intent — read the z.
- `Controls.TextField` swallows the press its own contentItem needs when a `MouseArea { anchors.fill: parent }` is declared inside it. The overlay is deliberate here (it signals the host for the layer-surface keyboard grab), so the fix is `focusField()` focusing whichever field was clicked — not deleting the MouseArea.
- Two numbers doing two jobs: `TimerState.maxMinutes` was both the slider range AND the hard clamp in `start`/`retime`/`nudge`/`parse`, so typing "45" started 30:00. Split into `maxMinutes` (slider) and `maxEntryMinutes` (24 h) with `maxMs` derived from the latter.
- Row budget is measured, not guessed: 7 px is the largest handle circle that fits a 38 px row under a 3 px bar on a 2 px bottom margin — it lands exactly on the row's bottom edge. `PillButton.implicitHeight` is 22, so a RowLayout centred at `-4` clears the bar band by ~3 px.
- A sub-agent can die on a network error (`getaddrinfo ENOTFOUND opencode.ai`) **after** writing every file it was given, leaving no report at all — and the file it fixed last was saved after the final reload, so the fix was on disk but not live. Re-verify from the filesystem; never assume a dead agent's last save is what the bar is running.

## 2026-10-03 — toasts rendered blank (icon + ×, no text)
- **`Item.left` / `.right` / `.top` / `.bottom` are NOT numbers in this Qt build — they return a `QQuickAnchorLine` object.** Measured live with a throwaway in-QML probe: `typeof card.left === "object"`, `typeof textCol.left === "object"`, `typeof root.left === "object"`, `typeof probe.left === "object"` (a bare `Item` with no anchors at all), and `card.left + 0` stringifies to `"QQuickAnchorLine()0"`. So ANY arithmetic on them is `NaN`, which Qt coerces to `0`. They stay **valid as anchor targets** (`anchors.right: dismiss.left`) — that is why ~100 such uses across the flyouts are all correct and this went unnoticed for so long. Use `.x` / `.y` / `width` / `height` for arithmetic and `.left`/`.right` for anchor targets only.
- That single trap was the whole bug. `ToastRow.qml` had `Column { width: dismiss.left - x - 6 }` → `NaN` → `0` → every child `Text { width: parent.width }` got `width: 0` and painted nothing, so the toast showed the icon and the × and no text. Measured proof: `col.w=0 col.ih=0 card.h=60`, while the Texts held perfectly good values (`t=[notify-send]`, `t=[LOG-PROBE]`, `t=[PAYLOAD-XYZ]`) with correct `implicitHeight` 14/16/14. `dismiss.x` is a plain number and in the same card-relative space as `x`, so `dismiss.x - x - 6` gives the correct 244.
- **Card height is the cheap tell.** `height: 20 + Math.max(40, textCol.implicitHeight)` measured 60, i.e. the column believed it was empty; populated it gives ~69. An elided `Text` at `width: 0` has `implicitHeight: 0`, so a zero-width bug hides in the geometry as well as in the pixels.
- **A comment describing a bug is not evidence of that bug.** `ToastRow.qml` carried a long note claiming `modelData.n` "evaluated to null as soon as the row was on screen, which showed as a toast with an icon and no text at all" — the exact symptom, diagnosed to the wrong layer, then "fixed" by switching to `required property var n`. The data path was never broken; the text was invisible for a layout reason. Re-derive the symptom before inheriting its explanation.
- **`scripts/check-reload.sh` cannot see warnings raised DURING a load.** `ReferenceError: Focus is not defined` lands BETWEEN `Reloading configuration...` and `Configuration Loaded`, so a "0 warnings since the last load" check returns clean while the bar is fully broken. Scan from the `Reloading configuration...` line to EOF (`awk '/Reloading configuration/{buf=""} {buf=buf $0 "\n"} END{printf "%s", buf}'`), never from `Configuration Loaded`.
- **Never branch-switch in this tree.** Checking out a branch lacking `Focus.qml` deleted the file and the merge recreated it; that reload failed to register the singleton, so every notification logged `ReferenceError: Focus is not defined` (`mine` falsy → `push()` returned early → **no toast at all**) *and* the file watcher died, so later saves produced no reload and `check-reload.sh` exited 1. Recovery: `quickshell -c tokyonight kill && quickshell -c tokyonight`, which restores both. A failed reload can kill the watcher, not just leave the old bar up. Commit in place on the current branch.
- **QML `console.log` DOES reach the live instance's log** (`/run/user/1000/quickshell/by-id/*/log.log`). The older "console.log never prints" note applies only to the offscreen `QT_QPA_PLATFORM=offscreen` probe harness. A temporary `Item { function dump() {...}; Component.onCompleted: Qt.callLater(dump) }` in the live config is by far the cheapest way to read real geometry and property values out of a running delegate — far better than inferring them from pixels.
- **Caveats when probing that way:** `Object.keys()` on a QML object returns `[]`, so it cannot be used to detect one; and reading a `QObject` property from inside a JS helper function can come back `undefined` even though a QML binding on that same property resolves it correctly (`text: root.n ? root.n.appName : ""` rendered `notify-send` while the probe's `root.n.appName` read `undefined`). Trust the binding, not the function-scoped read.
## 2026-10-04 — forget × on paired bluetooth rows; four traps worth keeping
- **A row-filling `MouseArea`'s `containsMouse` goes FALSE when the pointer enters a SIBLING `MouseArea`, and that hides anything the row reveals on hover.** Qt's `deliverHoverEventRecursive()` walks `paintOrderChildItems()` in reverse and **breaks at the first hovered leaf, propagating hover to ANCESTORS only — never to siblings.** So `hovered: hover.containsMouse` plus a sibling `MouseArea` inside the revealed widget is a self-destruct loop: enter the button -> sibling becomes the hover leaf -> `containsMouse` false -> widget `visible: false` -> it removes itself from under the cursor -> the next motion event brings it back. Measured per 1px step across the plate: `VVVVVV.V.V.V.V`, 10 drops. The consequence was not cosmetic — **one extra mouse-move before the press made the click land on the row and TOGGLE connect/disconnect instead of forgetting**, the opposite action, and it looked successful. Fix: `forgetShown: forgetable && !busy && (dr.hovered || forgetMouse.containsMouse)`. Stable, not circular: the row term bootstraps it, the child term holds it. An `onEntered`/`onExited` latch on the row MouseArea does **NOT** work — same `HoverLeave` path. **Whenever a hover-revealed control is a sibling MouseArea of the thing detecting the row hover, OR in the child's `containsMouse`.**
- **`z: 1` and declaration order were both correct, and the bug still shipped.** The reviewer confirmed click isolation does hold whenever the × is visible; only *when it is visible* was broken. A correct stacking argument says nothing about reveal state.
- **A test whose baseline is `git show HEAD:file` is destroyed by the commit that introduces the feature.** It passed uncommitted (HEAD = pre-change) and went permanently red the moment it was committed (HEAD = the change; the `forgetW == -1` sentinel flipped to 20). Pin the baseline to the *parent* of the commit that introduced the marker: `git log --format=%H -S 'forgetable' -- SettingsFlyout.qml | tail -1` then `${intro}^`, falling back to `HEAD` when that search is empty. **Re-run a suite after committing, not only before** — "green pre-commit" is the one state in which a HEAD-baseline test is guaranteed to lie.
- **Assigning a property that has a binding SEVERS it.** The probe set `hovered: true` directly, so `hover.containsMouse` was never evaluated anywhere in the suite; sabotaging it to `property bool hovered: false` (× impossible for a real user) still gave 24/24 ok. Drive hover from a real synthetic `QMouseEvent` into the row's own `QQuickWindow` and let the binding resolve.
- **`scripts/check-reload.sh` reports on the WRONG instance once the probe suite has run.** It takes `ls -t /run/user/1000/quickshell/by-id/*/log.log | head -1`, and the forget probe launches its own throwaway quickshell instances with their own log dirs — so the newest log is a `/tmp/.../probe.qml` and the script prints `Configuration Loaded` for a config that was never the bar. **Identify the live bar by its Shell ID** (`874b47e0f79f6b7f215ff9cd461939f6` for tokyonight, also the target of the `.qmlls.ini` symlink) and read that dir's `log.log`, or match `Launching config:` against the real `shell.qml`. A probe suite and a reload checker that both trust "the newest log" are the same bug twice. The probe also leaves a `by-id` dir per run — ~150 had piled up.
- **`Unable to assign [undefined] to QColor` in the live log is a truncated `Tokyo.qml`, not warm-up noise.** 31 .qml files reference `Tokyo.*`; with the singleton at 0 bytes every colour is undefined, the config still reports "Configuration Loaded", and the bar renders with invalid colours.

## 2026-10-03 — clock flyout: corners, spring, cross-fade, two clocks
- **`Bar.qml`'s `import Quickshell.Hyprland` is load-bearing and an unused-import sweep will flag it.** `Bar.qml` declares a `PanelWindow` and sets `exclusiveZone` but never sets `layer:` — the import is what registers the Hyprland layer-shell backend, and without it `PanelWindow` is not a layer surface and the desktop draws over the bar. Confirmed by contrast: all nine `PopupWindow` files in the tree import nothing Hyprland-related and work fine, and `Bar.qml` is the *only* file with a layer surface. Same trap, smaller: `NetworkMonitor.qml`'s `import Quickshell.Io` was a genuine unused import (it spawns nothing; `Poll` owns the `Process`), so the heuristic is right there and wrong on `Bar.qml`.
- **A `SequentialAnimation` wrapping a single `NumberAnimation` is a fossil, not a design.** `ClockFlyout.qml`'s `openAnim` documented a 1.04 spring overshoot at length while animating `t` to exactly `1`, so every `Math.min(1, t)` and clamped `mix()` downstream had nothing to clamp and the morph decelerated into a dead stop — it read as *placed*, not *drawn*. The corroborating evidence for the missing second stage was: `room: 18 // transparent margin for the overshoot` (literally named for it), clamps that exist only to survive 1.04, and comments referencing "a ~300 ms morph" while the animation ran 200 ms. Restoring it to 180 ms out + 120 ms back made three stale comments true again. **When a value has guards, margins and prose defending a behaviour it no longer has, treat the guards as the spec.**
- **Measure the 1.04 peak against the window before trusting it.** `shape.width` peaks 7.4 px/side past `panelW` against 18 px of `room`; height cannot clip until ~18 time zones (`rowH: 22`, clip needs 397 px of tail) where `clock-panel.sh` lists 3. Sampled 53 frames across `t ∈ [0, 1.04]`: zero clipped, 10.6 px slack at the peak, and at rest the panel sits *exactly* 18 px inside the window — `room` is consumed to the pixel, which is what confirms it was sized for this.
- **QML `Text` defaults to `horizontalAlignment: Text.AlignLeft`.** The clock date looked ~4 px off because `readings` is as wide as the widest of the three looks (the 13 px bold time fills it) and *neither* Text set an alignment, so the narrower 9 px date sat left-aligned in a box sized by the line above it. Off-centre only shows against a wider sibling — which is why the time looked fine and the date did not.
- **Two `Timer`s at 1000 ms disagree on the phase, not just the value.** `Clock.qml` owns the clock precisely because "a second Timer starts at its own instant, and the seconds digit of a cross-fading time reading is the last place a one-second disagreement would be visible" — and `ClockFlyout.qml`'s *face* obeyed that (`now: root.pill.now`) while the panel's date/time lines ran their own Timer. Both were on screen together for the whole morph, one inside the pill and one inside the panel. Hoisted to one `readonly property var clock` that prefers the pill's. **Watch for this when a fallback timer is left `running: true` and something stops reading it** — I repointed the display lines but missed the boot-timestamp computation, which then read a `now` frozen at construction.
- **Offscreen render recipe for measuring corner geometry** (images cannot be viewed in this harness, so radii must come from pixels): `QT_QPA_PLATFORM=offscreen quickshell -p ./probe.qml` with the real joint geometry and a `grabToImage` save, then a Python/PIL scan of the silhouette. That is how the six resting corners were confirmed to wear *three* radii (pill top pair 10, panel bottom pair 10, joint fillets 16). `fillet` was `min(drop - pillRadius, shape.y)` = 16 — the largest arc that *fits*, but larger than every other corner. Capping at `panelRadius` still fits (10 is inside the widget's straight run, 10..16) and makes all six agree. Note a 0-radius SVG arc is illegal, hence the `Math.max(0.1, …)`.
- **A read-only `explore` sub-agent launched for a dead-code audit never reported** — `list-child-sessions` showed `Updated == Created` across ~15 minutes. Budget for stalled agents: the audit was cheaper to run inline (`for f in *.qml; do grep -l …` per file) and found zero orphan QML files, zero orphan scripts, and exactly one real unused import in ~4 tool calls. Two consecutive dispatch failures on one ticket is the signal to stop delegating that slice.

## 2026-10-03 — "no text" that was never missing: measuring ink honestly
- **Exact-RGB matching reports "no text" even when text is fully drawn.** Glyphs are subpixel-antialiased, so almost every glyph pixel is a fringe, not the token colour. Counting pixels equal to `Tokyo.fg` returned zero while the toast was plainly full of text. **Measure ink as a difference from the local background, with a tolerance — not as a match against the ink colour.** Once switched, the same grab gave 253/344/344 px per line, and an isolated `textCol` grab gave 1077.
- Any "nothing is drawn here" conclusion needs an **idle baseline in the same run**. Counting "pixels that are not `panelFill`" over a region that overlaps the bar or the wallpaper measures the chrome and returns the same number for every input — a clean-looking result that is worthless.
- The NOTIFICATION lines (`app=`/`summary=`/`body=`) in `~/.local/state/quickshell/tokyonight/notifications.json` are what separates "the data never arrived" from "the data arrived and was not drawn".
- **A downsample erases text silently**; render at 1 logical pixel per character or the thin strokes simply are not in the image you analysed.
- **`layer.enabled` is not a fix for text on a popup surface.** The working theory was that text drawn straight to the xdg-popup surface is discarded and only survives through an FBO. A/B'd inside a single toast — `layer.enabled: true` on the summary `Text` only, its two neighbours left plain — and all three lines read fine. The earlier "it worked" report was the user finally looking at the right monitor. **When a "fix" is confirmed by a user who also moves between monitors, A/B it inside one object before keeping it.**
- **`hyprctl clients` does not list quickshell windows at all** (0 matches for any of the 9 popups or the 3 bars; total clients was 5). To prove per-instance behaviour, drop a `console.log("TAG")` in the function, count occurrences in the live log after one event, then remove it — `push()` logging three times proved all three per-monitor `Toast` instances took the notification.
- **`git commit` commits the whole index, not just what you just staged.** A memory file staged earlier got swept into an unrelated code commit. `git add <file>` does not reset that. Unstage the intruder (`git reset HEAD <path>`) or use `git commit --only <path>`; check `git show --stat` after every commit.

## 2026-10-03 — the clock was jittering because its own width measured its digits
- **`TextMetrics.width` is not constant for a fixed-width format.** `ClockFace.qml` measured `HH:mm:ss` from the *live* text and drove `contentW` → `implicitWidth` → the pill's width from it. Measured per digit: `0,2,3,4,5` → 63 px, `1,6,7,8,9` → **64 px**, same 8 characters. `fc-match` resolves the Bold face fine, so this is Qt rounding each glyph's advance separately, not a missing font. Result: the pill resized every second the seconds digit happened to change width, the bar's layout re-centred, and the clock visibly slid sideways — while the flyout's copy, centred on the magnet, sat still. **Symptom was reported as "the clock appears twice"**: a 1 px horizontal offset between two copies of the same text reads as a double. Any `TextMetrics` that sizes a layout must measure a *fixed worst-case sample*, not the live string.
- **A duplicated copy of one widget must be aligned by construction, and can still drift.** Here the bar's copy is centred by its parent's layout and the flyout's by `magnetItem`, so the two agree only while the measured width is constant. Fixing the jitter fixed the doubling; there was no second alignment bug to chase. Worth knowing before adding a "make the flyout's copy line up" fix — measure whether they are *supposed* to line up first.
- **`Repeater`'s delegate must be an `Item`.** `TextMetrics` is a `QObject`-style value type, so `Repeater { model: [10 digits]; TextMetrics {…} }` fails with `Delegate must be of Item type`. To sweep a set of strings, declare N `TextMetrics` by hand and index an array literal of their ids, or wrap them in an `Item` and read `.data[i]`. 135 explicit ones measured both formats' worst case in one reload.
- **`xInWindow` / `yInWindow` are not exposed in this quickshell QML binding** — they read `undefined`, so a window-relative position is not obtainable that way. `hyprctl -j layers` *is*, and it is keyed by output name (`hyprctl -j layers | jq '.["HDMI-A-1"].levels'`), giving each surface's `x/y/w/h` and `namespace` — the bar showed up as `level 2, x=0 y=0 w=1920 h=34`. That is how to get real on-screen geometry of a quickshell surface.
- **To make a *real* popup map from a probe, call the flyout's own open path**: `flyoutHost.toggleFor(this, magnet)` from a temporary `Timer` in `Clock.qml`. `grabToImage` on a popup's items fails with `item is not attached to a window` until it maps for real, so a probe that pokes properties without going through the real toggle can never capture it.

## 2026-10-04 — `check-reload.sh` can report success from a dead instance
- **`scripts/check-reload.sh` picks the newest-mtime `/run/user/1000/quickshell/by-id/*` dir, and a killed instance's log can be the newest.** It returned exit 0 off `t45t327emt` while the live shell (`4ivn227emt`, PID 1113916) had been failing to load for minutes. Confirmed twice in one evening, by two unrelated tickets. A green `check-reload.sh` is necessary, not sufficient.
- **Read the live PID's own log instead.** `ls -l /proc/<pid>/fd | grep -o '/run/user/1000/quickshell/by-id/[^/]*'` is authoritative — it follows the open fd, so it cannot be fooled by a stale directory. Then scan from the last `Reloading configuration...` to EOF (see the `Focus is not defined` note above for why scanning from `Configuration Loaded` is not enough).
- **`kill <pid>`, not `quickshell -c tokyonight kill`, to stop an instance.** The autostarted bar runs as a bare `/usr/bin/quickshell` with no `-c`, so the `-c`-matched kill silently skips it and you end up with two bars loading the same directory. Also leaves the dead instance's by-id dir as the newest, which is what fed the false pass above.
- **Migrating a property across several files takes the whole config down, silently.** Deleting `glyphMix` from `ClockFace.qml` while `ClockFlyout.qml` still assigned to it gave `Cannot assign to non-existent property "glyphMix"` → `Type Bar unavailable` → the entire config failed to load, and the *old* bar stayed on screen looking fine. Same again with `topMargin` set at object level on a `GridLayout`. **In a coupled change, grep the whole tree for every reader of a property you are about to delete, in the same pass that deletes it.**

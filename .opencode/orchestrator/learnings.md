# orchestrator learnings

## 2026-09-28 — tokyonight quickshell config (first run)
- Repo facts: config at `~/.config/quickshell/tokyonight`, launched `quickshell -c tokyonight` (v0.3.1, Arch), hot-reloads on save. No build system; checks are `bash -n`, running the scripts, and the reload log.
- Verification without qmllint: `quickshell -c tokyonight log` — success is `Reloading configuration...` followed by `Configuration Loaded`; a failed reload keeps the OLD bar running and only pops an overlay, so never trust the screen. (2026-09-28 correction: `opencode debug lsp diagnostics` does NOT exist in opencode 2.0.18 — `debug` has only agents/config/paths. There is no qmlls, no qmlformat, and quickshell has no validate mode, so structural review plus manual read-through is the only QML check available.)
- `Quickshell.iconPath(name, true)` (0.3.1) resolves freedesktop theme names and returns "" on a miss; `hasThemeIcon()` is the predicate. Works with no `//@ pragma IconTheme` — the active GTK theme is picked up. A plain `Image { source: ... }` renders the result, SVG included.
- Dead code to be careful with: `TrayIcon.qml` + `scripts/icon-resolve.sh` were retired with the tray merge but left on disk; the `find`-based resolver cost 3.9 s per miss. Prefer the built-in.
- Sub-agents on some providers refuse to run from this host ("free tier can only be used from within OpenCode") — retry with a different agent type.
- 2026-09-28: QML `Image.source` is url-typed, so `source === ""` is ALWAYS false (measured: `source === ""` false, `String(source) === ""` true). Test `icon.status === Image.Null` instead. A url/string compare as a visibility guard silently blanks cells and never throws.
- 2026-09-28: SNI `icon` is not a theme name — Steam sends a full `image://icon/steam_tray_mono?path=...` URL, others send `image://qspixmap/N/M`, openRGB sends an empty `IconName` (quickshell synthesizes a pixmap URL). Pass any `://` string through untouched; `Quickshell.iconPath` cannot resolve them.
- 2026-09-28: a sub-agent that edits a live config and dies (rate limit) leaves instrumentation behind. Always `cp` aside + restore + prove with sha256 against `git show HEAD:file`; check `git status` on the live file FIRST after any sub-agent error.
- 2026-09-28: only one process can own StatusNotifierWatcher, so a second `quickshell -p` probe sees 0 SNI items. Read tray state from the LIVE instance's log (instrument + `quickshell -c tokyonight log`) or from D-Bus directly (`busctl --user introspect :1.NNN /StatusNotifierItem`).
- 2026-09-28: a failed hot-reload leaves the OLD bar on screen, so the screen always looks fine. Only the log distinguishes success.
- 2026-09-28: `~/.config/hypr` is a SECOND config tree, separate from the quickshell one, and has NO git. Its only history is 7 `hyprland.lua.bak*` files. Binds live there; the ledger still lives under the quickshell tree. Expect to ask before `git init` it.
- 2026-09-28: `hyprland.lua` verification chain: `luac -p` (syntax only — it does NOT catch a nil `hl.dsp.*` field) -> `hyprctl reload` (once, live compositor) -> `hyprctl binds` (the real proof). A config that throws at load keeps the OLD config, so a bad field is invisible except as a bind that fails to appear.
- 2026-09-28: `hl.dsp.window.close()` exists in Hyprland 0.56.2 (graceful) alongside `hl.dsp.window.kill()` (SIGKILL). `repeating = true` is a real bind option already used at hyprland.lua:507-522 — it re-fires while the key is HELD, which is not the same as a self-paced "repeat until the window is gone" loop.
- 2026-09-28: Hyprland modmask arithmetic for spotting collisions: SUPER=64, CTRL=4, SHIFT=1, ALT=8. `hyprctl binds` output gives modmask+key, so three C binds coexist as 64 (kill), 65 (tray), 68 (close).
- 2026-09-28: the tokyonight bar talks to Hyprland ONLY via `hyprctl` through `Quickshell.execDetached`; the `Hyprland` singleton is imported for observation only (`onRawEvent`, `monitorFor`, `workspaces`, `focusedMonitor`), never dispatch. The bar has no `CustomShortcut`/`IpcHandler`/`Quickshell.Io` at all — reaching for a shell-side shortcut means building an IPC layer from scratch.
- 2026-09-28: **`hl.dsp.*` returns a descriptor, it does not fire on its own** — it only acts when handed to `hl.dispatch()` or `hl.bind()`. A bare `hl.dsp.window.close()` statement is a silent no-op (forum #1591; "bites people constantly"). Passing it to `hl.bind()` IS the working path, which is why the `SUPER+CTRL+C` bind needs no wrapping.
- 2026-09-28: **Hyprland does not escalate repeated close requests.** `close()` re-sends the identical `xdg_toplevel.close` / `WM_DELETE_WINDOW` forever. So a "keep re-asking until it dies" loop does NOT rescue an app that genuinely ignores the request — it only covers a first request eaten by a `noclosefor` window rule (repeat requests then rejected with "can't close window, it's not closeable yet" until the window ages in). Repeating is near-worthless; a grace period then SIGTERM/SIGKILL is what actually escalates.
- 2026-09-28: `hl.dsp.window.signal({signal=N})` exists (N 1-31), and `hl.timer(fn, {timeout=ms, type="repeat"|"oneshot"})` is a real native timer (no `hl.sleep`, no coroutine yield point). A keybind callback gets 100 ms, a timer callback 50 ms. Timers must be held in a variable outliving the callback — `onTimerFire` gates on `strongRef() > 2` and drops otherwise. That is how a self-paced close loop would be built with no shell script; not built, user chose the single request.
- 2026-09-28: XWayland caveat — `close()` sends `WM_DELETE_WINDOW` only if the app advertises it, else `xcb_kill_client`, a hard kill. On such apps the "graceful" bind is a kill with extra steps, silently. Native Wayland apps that ignore the request are simply left open.
- 2026-09-28: `hyprctl dispatch closewindow` is BROKEN under a Lua config — HyprCtl rewrites the arg to `hl.dispatch(<arg>)`, and the legacy names (`closewindow`, `killactive`, `forcekillactive`) are hyprlang-only. Under Lua you must write `hyprctl dispatch "hl.dsp.window.close()"`. Also note `killactive` == graceful close and `forcekillactive` == SIGKILL: the names read backwards.
- 2026-09-28: `quickshell -c tokyonight log` prints the WHOLE journal since instance start, not just the last reload. Removed instrumentation still shows up as historical output. Scope every claim to lines after the LAST `Configuration Loaded` — otherwise you will "discover" a bug that was fixed runs ago.
- 2026-09-28: `Quickshell.iconPath(name, true)` is CASE-SENSITIVE. Measured: `"samrewritten"` -> `image://icon/samrewritten`, `"SamRewritten"` -> `""`, `hasThemeIcon` agrees. A window class like `org.samrewritten.SamRewritten` therefore misses even though the icon exists at `/usr/share/icons/hicolor/64x64/apps/samrewritten.png`. Retry the last dotted segment lowercased, but try lower case LAST — `org.openrgb.OpenRGB` resolves only in its own casing.
- 2026-09-28: **nerd-font codepoints are not what the FA4 name suggests.** U+F0C8 is `fa-square`, not a wrench — that IS U+F0AD. A wrong "generic" glyph therefore renders as a literal box and gets reported as a broken icon. Verify a codepoint with fontTools (`getBestCmap` can return a list — merge `f['cmap'].tables` that are `isUnicode()`), and resolve the family with `fc-match` FIRST: family "JetBrains Mono Nerd Font" maps to the *Proportional* `JetBrainsMonoNerdFont-Regular.ttf`, not the Mono face, so checking the wrong file proves nothing.
- 2026-09-28: `RegisteredStatusNotifierItems` on `org.kde.StatusNotifierWatcher` is a D-BUS **property**, not a method — `busctl --user call` fails with "No such method". Use `busctl --user get-property org.kde.StatusNotifierWatcher /StatusNotifierWatcher org.kde.StatusNotifierWatcher RegisteredStatusNotifierItems`, then `introspect` each returned `:1.NNN/path` for `IconName`/`Id`/`Title`. This is how to find out that only 2 of your "tray" apps are real SNI items.
- 2026-09-28: verify quickshell UI with `grim` + pixel analysis instead of screenshots. Pick the monitor by name from `hyprctl monitors -j` (`grim -o 0` fails). `grim` captures PHYSICAL pixels, so logical = /2 at scale 2 — a slip here silently analyses the wrong region. `pillBg` at alpha 0.9 composites to about (44,48,72) over bar bg (22,22,30). A glyph is sparse strokes; a solid box is ~98% fill with <40 distinct colours; artwork is 100+ distinct colours. Count pixels matching a colour with ALL channels within tolerance — an ANY-channel match is far too loose and reports AA fringes as glyphs.
- 2026-09-28: `pgrep -f 'hyprctl|jq'` matches its own command line and reports a permanent phantom process count. Use `pgrep -xc <name>` for exact-name counting when measuring whether a poll actually spawns anything.
- 2026-09-28: the tokyonight QML files use 4 spaces — `grep -cP '\t'` is 0 across all of them. Do not tell a sub-agent to use tabs; verify the file's actual convention first.
- 2026-09-28: when a reviewer or brief asserts a premise, check it before complying. Two of this run's briefs were wrong (a `SUPER+CTRL+SHIFT+C` bind that never existed; "tab indentation" against a spaces repo) and a review finding was rejected because its stated reason was false (`Bar.qml`'s unused `Quickshell.Hyprland` import was already an orphan at the base commit, so it was not residue of the diff). A finding with a false premise is worse than no finding — executing it enlarges the diff for nothing.
